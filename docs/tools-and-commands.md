# Agent 工具集与斜杠命令手册 (Tools & Commands)

本文档面向大模型提示词设计者、二次开发者与高级使用者，全面阐述 **kujira** 的 16 大 Agent 专属工具契约与 10 大纯两字中文斜杠命令规范。

---

## 1. 单聊专属预设 (`kujira-session`) 机制

为保障代码工程质量与会话安全性，kujira 摒弃了将工具全局挂载到宿主 `ctx.tools` 的传统做法，而是通过 **单一真相源（SSOT）** 动态注册 `kujira-session` 专属预设：

- **工具强隔离**：单聊专属工具（如 `send_qq_message`、`recall_message`、`list_faces` 等）仅对装配了 `kujira-session` 预设的 QQ 单聊会话可见，**绝不向 DSH WebUI 常规会话或审查会话泄露**；
- **轻量化提示词注入**：预设配置 `complete: true`，在会话创建期彻底覆盖 DSH 默认庞杂的 Coding 提示词，仅注入专注 C2C 单聊的拟人化 Prompt；
- **全要素工具集拼装**：自动装配文件系统（`tool-fs`）、跨平台 Shell（Windows 激活 `tool-pwsh` / Linux 激活 `tool-bash`）、官方 Web 搜索（`tool-web`）、技能发现（`tool-skill`）、交互提问（`tool-ask-user`）与会话压缩能力组（`compaction`）。

## 2. 16 大 Agent 专属工具详解

所有专属工具均严格遵守 **DSH Lossless JSON 输出红线**：返回结果通过 `toLosslessJson()` 递归剔除所有 `undefined` 字段，确保 Agent 调用平稳无报错。

### 2.1 消息收发与自愈工具

#### 1. `send_qq_message`（单聊消息发送）
- **功能描述**：向当前单聊对端发送文本或富文本排版消息。遵循「用户侧静默原则」，模型回复用户必须显式调用此工具。
- **输入参数**：
  - `text` (*string*, 必填)：发送内容。原生支持 Markdown 语法（标题、表格、列表、引用卡片、代码高亮等），字符上限 6000 字符；
  - `reply_to` (*string*, 可选)：引用的目标消息短 ID（如 `msg_1` 或 `msg_self_2`）。日常对话默认省略，仅在隔很久引用或逐条对应时传入；
  - `segmented` (*boolean*, 可选)：是否允许在内容过长时拆分多条发出（默认 `false`）。
- **执行逻辑**：
  - 工具自动将短 ID 转换为底层真实的 `message_reference` 锚点；
  - 遇到被动回复过期（`40034128`）自动平滑降级；
- **返回结果**：返回生成的消息短 ID（`{ success: true, message_id: "msg_self_5" }`）。

#### 2. `recall_message`（自主消息撤回）
- **功能描述**：自主撤回机器人自身在 2 分钟（120 秒）内发出的指定消息。
- **输入参数**：
  - `message_id` (*string*, 必填)：待撤回的消息短 ID（如 `msg_self_1`）或真实消息 ID。
- **约束红线**：
  - 受腾讯 QQ 开放平台硬时限约束，超过 120 秒撤回将失败（平台返回 `40064004` / `40061002`）；
  - 仅可撤回机器人自身发送的消息，无法撤回用户发来的消息。

### 2.2 聊天历史与等待工具

#### 3. `read_chat_history`（历史漫游与附件索引）
- **功能描述**：从本地 SQLite 数据库中按倒序读取当前单聊的历史消息，获取消息短 ID、时间戳、本地媒体附件路径及文本摘要。
- **输入参数**：
  - `limit` (*number*, 可选，默认 20)：获取的消息条数上限（最大 100）；
  - `before_id` (*string*, 可选)：游标短 ID，拉取早于该 ID 的历史。
- **返回结构**：包含消息列表、发送者标识、短 ID 与本地已落盘的图片/语音路径。

#### 4. `wait_for_user_messages`（等待用户输入补充）
- **功能描述**：暂时挂起当前 Agent 回合，主动等待用户发送更多图片或后续文字说明（如用户发了一张图但没配文字，或话只说了半截）。
- **输入参数**：
  - `timeout_seconds` (*number*, 可选，默认 15)：等待超时秒数（5~60 秒）；
  - `reason` (*string*, 可选)：等待原因。
- **约束规范**：常规闲聊或单纯表情包互动切勿滥用等待，仅用于明确需要用户补充关键上下文的场景。

---

### 2.3 富媒体下发工具

#### 5. `send_file`（本地多媒体与文件下发）
- **功能描述**：将本地图片、语音、视频或常规文件分片上传至 QQ 开放平台并发送给单聊对端。
- **输入参数**：
  - `file_path` (*string*, 必填)：本地文件的绝对路径或工作区相对路径；
  - `file_type` (*string*, 选填)：媒体类型（`image` / `video` / `voice` / `file`，缺省按扩展名自动推断）。
- **底层机制**：采用官方标准四步分片上传管线，单片按 512KB 分块并自动重试，秒级复用 `file_info`。

### 2.4 表情资产库工具集（默认常驻）

#### 6. `list_faces`（检索表情库）
- **输入**：`tag?: string`（按标签检索）、`emotion?: string`（按情绪检索）、`limit?: number`。
- **输出**：匹配的表情条目（包含 ID、标签、情绪描述与本地相对路径）。

#### 7. `send_face`（发送表情包）
- **输入**：`face_id: string`。
- **逻辑**：读取本地表情库图片，通过 OpenAPI 发送给用户。

#### 8. `collect_face`（收录新表情）
- **输入**：`file_path: string`（通常来自聊天中用户发送并落盘的图片路径）、`tags: string[]`（标签列表）、`emotion: string`（主导情绪）。
- **逻辑**：将图片收纳进表情目录，记录至数据库，受 `face_store_max` 与满额淘汰策略（默认 `reject` 拒绝新增，支持配置 `evict_lru` 淘汰）约束。

#### 9. `manage_faces`（维护表情资产）
- **输入**：`action: 'delete' | 'update'`, `face_id: string`, `tags?: string[]`, `emotion?: string`。

---

### 2.5 双层记忆系统工具集

#### 10. `read_memory`（读取记忆）
- **输入**：`target: 'user_profile' | 'session_memory'`。
- **特性**：仅支持读取当前单聊用户所属的画像与会话规则，跨会话读取会被安全拦截。

#### 11. `create_memory`（创建初始记忆文档）
- **输入**：`target: 'user_profile' | 'session_memory'`, `content: string`。
- **硬限制**：字符数严格受预算限制（默认 2200 字符），超限拒绝创建。

#### 12. `edit_memory`（更新记忆文档）
- **输入**：`target: 'user_profile' | 'session_memory'`, `content: string`。
- **最佳实践**：记忆应提炼长期稳定事实、偏好与约定，一次性报错和排查细节严禁写入。

---

### 2.6 黑话学习系统工具集（默认常驻）

#### 13. `query_slang`（查询黑话详细释义）
- **输入**：`term: string`。
- **逻辑**：当用户发言命中 System Prompt 中的 L1 黑话招牌句式索引时调用，获取该梗的完整释义、触发情境与使用范例。

#### 14. `record_slang`（收录新黑话）
- **输入**：
  - `term` (*string*)：黑话/词条名称；
  - `definition` (*string*)：含义与来源背景；
  - `cue` (*string*)：触发情境与招牌句式（如“别人X而我X”）；
  - `examples` (*string[]*)：例句。

#### 15. `manage_slang`（更新或删除黑话）
- **输入**：`action: 'delete' | 'update'`, `term: string`, `definition?: string`, `cue?: string`。

---

### 2.7 定时任务引擎工具集

#### 16. `schedule_task` / `manage_scheduled_tasks`
- **功能描述**：安排在指定时间或延时后自主唤醒 Agent，向用户汇报进度、提醒备忘或跟进待办。
- **防污染保证**：定时任务唤醒由 `SystemEventHub` 以系统标头注入，彻底杜绝系统事件被模型误当作聊天对话回复。

## 3. 10 大纯两字中文斜杠命令全景

在 QQ 单聊中直接发送带有 `/` 前缀（全角 `／` 亦兼容）的中文指令即可触发。指令在路由层直接拦截执行，**不消耗大模型推理 Token**。

### 3.1 指令速览表

| 指令 | 语法格式 | 描述 | 示例 |
|---|---|---|---|
| **/状态** | `/状态` | 查看系统运行概况、模型名称、思考档位与连接健康度 | `/状态` |
| **/模型** | `/模型 [名称]` | 浏览可用模型列表，或无缝切换当前单聊的大模型 | `/模型 deepseek-reasoner` |
| **/思考** | `/思考 [开/关/预算]` | 调节当前模型的推理思考深度（Reasoning Effort） | `/思考 8192` 或 `/思考 关` |
| **/新建** | `/新建` | 结束当前会话轮次，就地开启全新会话（长期记忆保留） | `/新建` |
| **/会话** | `/会话 [序号/标题]` | 浏览历史轮次列表，支持无缝切回历史会话 | `/会话 2` |
| **/用量** | `/用量` | 统计当前单聊会话累计消耗的 Token 数量与上下文占用 | `/用量` |
| **/压缩** | `/压缩` | 立即触发 Compaction 会话历史压缩，释放上下文 | `/压缩` |
| **/停止** | `/停止` | 紧急中断正在生成或运行中的 Agent 回合 | `/停止` |
| **/权限** | `/权限 [模式]` | 切换会话运行权限（只读 / 工作区写入 / 完全访问） | `/权限 完全` |
| **/帮助** | `/帮助` | 输出所有可用斜杠指令的帮助卡片 | `/帮助` |

---

### 3.2 重点指令行为细节

#### 1. `/权限` 指令与安全级别
- **语法**：`/权限 只读` | `/权限 编辑`（工作区写入） | `/权限 完全`（完全访问）；
- **工作区写入 (`workspace-write`)**：默认初始权限。Agent 仅允许在 DSH 指定工作区内读写文件与执行受限命令；
- **完全访问 (`danger-full-access`)**：高危模式。放行全局文件系统访问与任意 Shell 执行权限。

> [!CAUTION]
> **安全红线**：由于单聊为一对一独占设计，**添加了机器人好友的用户默认具备执行 `/权限 完全` 的能力**。切勿将不可信的用户添加为开发体验用户！

#### 2. `/压缩` 指令与 Compaction 机制
- 当对话历史较长、Token 消耗过大时，执行 `/压缩`；
- 插件将调用 DSH 官方 `compaction` 服务，对历史轮次进行智能摘要与无损压缩，剪除中间冗余 Tool Result，极大节省推理成本并避免溢出。

#### 3. `/新建` 与 `/会话` 的版本化轮次
- 执行 `/新建` 会将当前会话归档，并在 SQLite 中为该用户分配下一个版本号标签（例如 `#1` -> `#2`）；
- 用户长期画像（`user_<openid>.md`）跨轮次持久存在，新会话开箱即能认出老朋友；
- 若想回到历史话题，发送 `/会话` 查看列表后，输入 `/会话 1` 即可平滑切换回 `#1` 会话。

## 4. 交互式提问（Ask User）与审批流

当大模型在单聊中调用 `tool-ask-user`（向用户澄清问题或提供选项）或触发敏感操作审批时：

- **单聊交互呈现**：问题与选项通过 `send_qq_message` 自动转化为美观的 Markdown 编号列表；
- **极简确认交互**：
  - 选项类：用户回复选项对应编号（如 `1` 或 `2`）；
  - 审批类：用户回复 `y` / `yes` 放行，回复 `n` / `no` 驳回。
- 用户回复后，系统立即接纳并将答案精准反馈回等待中的 Agent 流程，形成丝滑闭环。
