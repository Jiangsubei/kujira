# 实测报告：QQ 官方 Bot 单聊消息类型、Markdown 渲染与引用交互

> **证据等级**：本文所有结论均来自 QQ 开放平台官方 Bot API v2 真实环境探针实测（对应探针：`scripts/probe-qq.ts`）。
> **核心原则**：腾讯官方文档在多处与线上实际行为不符，本文结论以实测请求与客户端实际渲染为准，未采信文档未验证条款。

---

## 1. `msg_type=0`（纯文本）与 `msg_type=2`（Markdown）边界实测

接口：`POST /v2/users/{openid}/messages`

| 测试组合 | 请求核心字段 | 服务端结果 | 客户端实际渲染 |
| --- | --- | --- | --- |
| 纯文本 | `msg_type: 0, content: "..."` | ✅ 200 成功 | 普通纯文本消息 |
| 仅 Markdown | `msg_type: 2, markdown: { content: "# ..." }` | ✅ 200 成功 | Markdown 正常渲染 |
| 同时传 `content` 与 `markdown` | `msg_type: 2, content: "...", markdown: { content: "# ..." }` | ✅ 200 成功 | Markdown 生效，`content` 被服务端静默忽略 |
| 仅传 `content` 无 `markdown` | `msg_type: 2, content: "..."` | ❌ HTTP 400 / `code=40034011` (`无效 markdown content`) | 未收到消息 |

**工程结论**：
1. 官方文档「传了 `markdown` 后 `content` 必须为空」并非硬失败约束，服务端会静默忽略 `content`；但作为卫生规范，发 `msg_type=2` 时只传 `markdown.content` 即可。
2. `msg_type=2` 时**必须保证 `markdown.content` 存在且非空**，否则触发 `40034011`。

## 2. 单聊 Markdown 渲染能力与 URL 限制实测

通过 `msg_type=2` 向单聊发送 10 类 Markdown 语法测试项，全部服务端返回 200 且用户客户端确认渲染正常、未露出原始 Markdown 符号：

| 测试项 | 文档是否列出支持 | 服务端 | 客户端真实渲染结果 |
| --- | --- | --- | --- |
| 表格（`\| a \| b \|` + 分隔行） | ❌ 未列出 | ✅ 200 | ✅ 渲染为真表格 |
| 围栏代码块（`` ```js ``） | ❌ 未列出 | ✅ 200 | ✅ 正常渲染为代码块（未露反引号） |
| 行内代码（`` `x` ``） | ❌ 未列出 | ✅ 200 | ✅ 正常渲染（无反引号残留） |
| 四级标题（`####`） | ❌ 仅列 `#`/`##` | ✅ 200 | ✅ 正常渲染 |
| 嵌套列表 | ✅ 已列出 | ✅ 200 | ✅ 正常渲染 |
| 块引用 + `***` 分割线 | ✅ 已列出 | ✅ 200 | ✅ 正常渲染 |
| `**加粗**`、`__下划线加粗__`、`~~删除线~~` | ✅ 已列出 | ✅ 200 | ✅ 正常渲染 |
| 2200 字符超长单行 | — | ✅ 200 | ✅ 完整收到，未触发长度拒收 |
| Markdown 链接 `[腾讯网](https://www.qq.com)` | — | ✅ 200 | ✅ 可点击链接，未触发 `40054010` |
| 裸 URL `https://www.qq.com` | — | ✅ 200 | ✅ 可点击链接，未触发 `40054010` |

### Markdown 公网图片补充实测

| 图片 URL 来源 | 服务端 | 客户端真实表现 |
| --- | --- | --- |
| GitHub 头像 URL（`avatars.githubusercontent.com`） | ✅ 200 | ⚠️ 显示 `[测试图]` 占位符 |
| 腾讯 COS 图（`cos.ap-guangzhou.myqcloud.com`） | ✅ 200 | ✅ 真实显示图片 |
| 百度 Logo（`www.baidu.com`） | ✅ 200 | ✅ 真实显示图片 |

**工程结论**：
1. **单聊 Markdown 实际支持度远超官方文档保守描述**：表格、围栏代码块、行内代码、多级标题均可正常渲染，无需退化改写为纯文本。
2. **单聊未受群聊 URL 白名单限制**：Markdown 链接、裸 URL 均未触发群聊错误码 `40054010`。
3. **Markdown 图片仅适用于平台可直接拉取的公网 URL**：遇到 GitHub 等境外/受限域名会退化为占位文字；发送本地生成图片仍必须走富媒体分片上传通道（`msg_type=7`）。
4. **中文 `#标题` 规范化建议**：无空格写法（如 `#标题`）建议在出站适配层补齐为 `# 标题` 以保证移动端稳定识别。

## 3. `msg_type=6` 输入中状态（`input_notify`）实测

请求体示例：
```json
{
  "msg_type": 6,
  "input_notify": {
    "input_type": 1,
    "input_second": 60
  },
  "msg_id": "<入站 msg_id>",
  "msg_seq": 1
}
```

**实测结果**：
1. 服务端返回 200 成功；20 秒静默观察窗内，手机 QQ 单聊顶部持续显示「正在输入…」。
2. 持续状态会在机器人发出**第一条正式出站消息后**被自动覆盖结束。
3. 发送 `msg_type=6` 后，同一 `msg_id` 后续使用 `msg_seq = 2..6` 连续发送 5 条普通消息均全部成功。

## 4. 单聊引用回复（`message_reference`）实测

> **文档偏差**：历史官方文档曾标注单聊 `message_reference`「暂未支持」，**线上实测完全可用**。

| 引用目标 | `message_reference.message_id` 取值来源 | 实测结果 |
| --- | --- | --- |
| 引用用户发来的入站消息 | `C2C_MESSAGE_CREATE` 事件 `message_scene.ext` 数组中的 `msg_idx=REFIDX_...` 字段值 | ✅ 200 成功，手机端以引用气泡形式显示原消息 |
| 引用机器人自己发出的出站消息 | 机器人发消息接口成功响应体中的 `ext_info.ref_idx` | ✅ 200 成功，手机端以引用气泡形式显示机器人原消息 |

**注意**：引用使用的是 `REFIDX_...` 形式的 `ref_idx` 索引，而非消息体的 `id`（`ROBOT1.0_...`）。

## 5. 文档口径与实测差异汇总

| 腾讯官方文档口径（不可轻信） | 线上实测结论 |
| --- | --- |
| 传了 `markdown` 后 `content` 必须为空 | 同时传入不会报错，`content` 被静默忽略；但 `msg_type=2` 缺 `markdown` 会报 `40034011` |
| Markdown 列表仅列出基础格式与 `#`/`##` | 表格、围栏代码块、行内代码、四级标题在单聊中全部正常渲染 |
| 单聊 `message_reference` 暂未支持 | 单聊完全支持引用入站消息与机器人自身历史消息 |
